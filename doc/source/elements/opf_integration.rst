Violation-Aware PandaProsumer and pandapower OPF Integration
=============================================================

Purpose
-------

This tutorial demonstrates a violation-aware interface between a
PandaProsumer shopping-center model and a ``pandapower`` optimal power
flow (OPF) calculation. The shopping center is represented in the grid as
one controllable active-power load. Its feasible power range is not chosen
arbitrarily. It is derived from the internal PandaProsumer model, which
contains the residual mall demand, CHP, booster heat pump, heat storage
and heat demand.

The script follows this high-level workflow:

1. Run PandaProsumer once in baseline mode.
2. Collect the feasible flexibility bounds of the shopping center.
3. Convert the PandaProsumer device-side flexibility into grid-side mall
   power bounds.
4. Add the shopping center to a Schutterwald low-voltage grid as a
   controllable load.
5. Run an AC power flow and check for voltage or loading violations.
6. Run OPF only if a network violation is detected.
7. Minimize deviation from the baseline mall consumption while satisfying
   grid constraints.
8. Send the OPF setpoint back to PandaProsumer.
9. Rerun PandaProsumer and verify that the OPF setpoint is internally
   feasible and tracked.

This is no longer only a direct target-tracking demonstration. The OPF is
now activated conditionally: if the baseline grid state has no violation,
no flexibility is requested. If a violation exists, OPF computes the
minimum necessary active-power adjustment of the mall load.

Modelled Shopping-Center Power Balance
--------------------------------------

The script defines the residual electrical mall demand as:

.. math::

   P_\mathrm{residual} = L - PV

where ``L`` is the synthetic mall load profile and ``PV`` is the synthetic
PV generation profile. In the code this is stored as ``flex_target_mall``.

The internal electrical device contribution is:

.. math::

   P_\mathrm{device} = P_\mathrm{CHP} - P_\mathrm{BHP}

where ``P_CHP`` is electrical power generated by the CHP and ``P_BHP`` is
electrical power consumed by the booster heat pump.

The resulting grid-side mall consumption is:

.. math::

   P_\mathrm{grid} = P_\mathrm{residual} - P_\mathrm{device}

Therefore, reducing the mall's grid import requires increasing the net
internal electrical contribution:

.. math::

   P_\mathrm{CHP} - P_\mathrm{BHP} \uparrow

In a downward-flexibility case, this usually means increasing CHP
electrical generation, reducing BHP electrical consumption, or combining
both actions while still satisfying the heat demand and heat-storage
constraints.

Time-Series Setup
-----------------

The script uses an 8-day hourly simulation horizon:

.. code-block:: python

   start = "2020-01-01 00:00:00"
   end = "2020-01-08 23:59:59"
   time_resolution = 3600
   frequency = "60min"

The mall electrical demand profile has morning and evening peaks. PV
follows a sinusoidal daytime profile. The baseline flexibility request is
zero for all timesteps:

.. code-block:: python

   flex_target_mall = L - G_PV
   baseline_flex_target_kw = np.zeros(n_steps)

The baseline flexibility request of zero means that the initial
PandaProsumer run computes the normal operating point without an external
flexibility activation request.

PandaProsumer Model Construction
--------------------------------

The function ``build_mall_prosumer`` creates the shopping-center
prosumer model. It builds the following controlled components:

* constant profile controller for time-series inputs,
* booster heat pump (BHP),
* separate BHP COP calculation controller,
* internal combustion engine CHP,
* heat storage,
* heat demand,
* optimization controller.

The most important mappings are:

* heat demand is passed to the heat-demand element,
* BHP and CHP thermal outputs are passed to the heat storage,
* heat storage output is passed to the heat demand,
* BHP COP is passed to the optimization controller,
* optimization-controller outputs are passed back to the BHP and CHP.

The optimization controller receives:

.. code-block:: python

   q_demand_kw
   p_flex_kw
   cop_bhp

and returns the device dispatch, especially:

.. code-block:: python

   p_el_bhp_in
   p_el_chp_out

These outputs define the internal electrical device contribution
``P_CHP - P_BHP``.

Collecting and Converting Flexibility Bounds
--------------------------------------------

The function ``run_mall_case_with_bounds`` runs the PandaProsumer time
series and extracts BHP, CHP, storage and heat-demand results.

It computes:

.. code-block:: python

   p_device_kw = res_chp["p_el_out_kw"] - res_bhp["p_el_floor"]
   p_grid_kw = flex_target_mall_series - p_device_kw

This gives the mall's grid-side power consumption for each timestep.

When ``collect_bounds=True``, the optimization controller also stores the
feasible device-side support and absorption limits. These are converted
into grid-side mall power limits using:

.. math::

   P_\mathrm{mall,min} = P_\mathrm{residual} - P_\mathrm{device,max\ support}

.. math::

   P_\mathrm{mall,max} = P_\mathrm{residual} - P_\mathrm{device,max\ absorption}

The resulting OPF-ready quantities are:

.. code-block:: python

   p_mall_min_mw
   p_mall_base_mw
   p_mall_max_mw
   flex_down_mw
   flex_up_mw

The interpretation is:

* ``p_mall_min_mw``: minimum feasible grid import of the shopping center,
* ``p_mall_base_mw``: baseline grid import,
* ``p_mall_max_mw``: maximum feasible grid import,
* ``flex_down_mw``: available load reduction from the baseline,
* ``flex_up_mw``: available load increase from the baseline.

If export is not allowed, all grid-side mall powers are clipped at zero.
This models the mall as a controllable load that may reduce consumption to
zero but may not export active power back to the grid.

Grid Preparation
----------------

The pandapower section uses the Schutterwald low-voltage network:

.. code-block:: python

   subnets = lv_schutterwald(separation_by_sub=True, include_heat_pumps=False)

The function ``prepare_grid_for_opf`` prepares a subnet for OPF:

* existing loads are fixed,
* existing static generators are fixed,
* voltage limits are assigned to all buses,
* loading limits are assigned to lines and transformers,
* wide external-grid limits are assigned so that the slack can balance the
  network.

The current demonstration limits are:

.. code-block:: python

   v_min_pu_std = 0.90
   v_max_pu_std = 1.10
   loading_percent_max_std = 150.0

These are relaxed demonstration limits. For a stricter DSO-style study,
they can later be replaced by normal low-voltage limits such as:

.. code-block:: python

   v_min_pu_std = 0.95
   v_max_pu_std = 1.05
   loading_percent_max_std = 100.0

Violation Check
---------------

The function ``check_grid_violations`` checks the grid state after a
successful power flow. It evaluates four categories:

* undervoltage,
* overvoltage,
* line overload,
* transformer overload.

The function returns:

.. code-block:: python

   has_violation, violations

where ``has_violation`` is a Boolean and ``violations`` is a dictionary
with the violating elements and their values.

This implements the DSO-style logic:

.. code-block:: text

   Run baseline AC power flow
   -> Check bus voltage and branch loading
   -> If no violation: no flexibility activation required
   -> If violation exists: run OPF

Controllable Mall Load in pandapower
------------------------------------

For every candidate subnet, the script chooses an LV bus that is not the
external-grid bus. The selected bus is around the 30th voltage percentile.
This avoids always placing the mall at the absolute weakest point but still
keeps it in a relevant part of the LV network.

The shopping center is then added as a controllable load:

.. code-block:: python

   mall_load = pp.create_load(
       net,
       bus=mall_bus,
       p_mw=p_mall_base_mw,
       q_mvar=q_mall_base_mvar,
       name="Shopping Mall load",
       controllable=True,
       min_p_mw=p_mall_min_mw,
       max_p_mw=p_mall_max_mw,
       min_q_mvar=q_mall_base_mvar - q_eps,
       max_q_mvar=q_mall_base_mvar + q_eps,
   )

This means pandapower OPF may choose the mall active power only within the
PandaProsumer-derived flexibility envelope:

.. math::

   P_\mathrm{mall,min} \leq P_\mathrm{mall} \leq P_\mathrm{mall,max}

The mall reactive power is almost fixed at zero by the narrow bounds:

.. math::

   Q_\mathrm{mall} \approx 0

Therefore, the current integration demonstrates active-power flexibility.

OPF Objective
-------------

The function ``run_mall_opf_min_deviation`` runs the OPF only after a
network violation has been detected. The objective is:

.. math::

   \min\; w\left(P_\mathrm{mall} - P_\mathrm{base}\right)^2

where:

* ``P_mall`` is the controllable mall active power selected by OPF,
* ``P_base`` is the baseline mall grid consumption,
* ``w`` is a weighting factor.

This objective means:

   Use as little flexibility as necessary while satisfying the grid
   constraints.

The quadratic objective is implemented with ``create_poly_cost``. The
expanded form is:

.. math::

   w\left(P_\mathrm{mall} - P_\mathrm{base}\right)^2
   = wP_\mathrm{mall}^2
   - 2wP_\mathrm{base}P_\mathrm{mall}
   + wP_\mathrm{base}^2

The cost coefficients are therefore:

.. code-block:: python

   cp2_eur_per_mw2 = weight
   cp1_eur_per_mw = -2.0 * weight * p_base_mw
   cp0_eur = weight * p_base_mw**2

The external grid receives zero cost. It balances the network but does not
define the flexibility activation.

OPF Constraints
---------------

The OPF is subject to the following constraints:

Mall flexibility bounds
~~~~~~~~~~~~~~~~~~~~~~~

.. math::

   P_\mathrm{mall,min} \leq P_\mathrm{mall} \leq P_\mathrm{mall,max}

These bounds come from PandaProsumer and represent the internal CHP, BHP,
heat-demand and thermal-storage feasibility.

Mall reactive-power bounds
~~~~~~~~~~~~~~~~~~~~~~~~~~

.. math::

   Q_\mathrm{mall,min} \leq Q_\mathrm{mall} \leq Q_\mathrm{mall,max}

In the current script, these bounds keep ``Q_mall`` approximately fixed at
zero.

Bus-voltage constraints
~~~~~~~~~~~~~~~~~~~~~~~

.. math::

   V_\mathrm{min} \leq V_i \leq V_\mathrm{max}

with the current demonstration values:

.. math::

   0.90 \leq V_i \leq 1.10

Branch-loading constraints
~~~~~~~~~~~~~~~~~~~~~~~~~~

.. math::

   \mathrm{loading}_\mathrm{line} \leq 150\% \\
   \mathrm{loading}_\mathrm{trafo} \leq 150\%

External-grid constraints
~~~~~~~~~~~~~~~~~~~~~~~~~

The external grid is allowed to balance active and reactive power within
wide limits:

.. math::

   -10 \leq P_\mathrm{ext} \leq 10

.. math::

   -10 \leq Q_\mathrm{ext} \leq 10

AC power-flow equations
~~~~~~~~~~~~~~~~~~~~~~~

The OPF must also satisfy the AC network equations. Therefore, the result
is not only an economic dispatch but a grid-feasible operating point under
the specified voltage and loading limits.

OPF-to-PandaProsumer Setpoint Conversion
----------------------------------------

The OPF returns a grid-side mall setpoint:

.. math::

   P_\mathrm{grid,setpoint} = P_\mathrm{mall,OPF}

PandaProsumer, however, tracks a device-side target:

.. math::

   P_\mathrm{device,target} = P_\mathrm{CHP} - P_\mathrm{BHP}

Using the grid-side balance:

.. math::

   P_\mathrm{grid} = P_\mathrm{residual} - P_\mathrm{device}

this is converted as:

.. math::

   P_\mathrm{device,target}
   = P_\mathrm{residual} - P_\mathrm{grid,setpoint}

In code:

.. code-block:: python

   p_grid_setpoint_kw = p_mall_opf_mw * 1000.0
   residual_load_selected_kw = flex_target_mall[selected_position]
   p_device_setpoint_kw = residual_load_selected_kw - p_grid_setpoint_kw

This target is then inserted into the PandaProsumer input profile at the
selected timestep:

.. code-block:: python

   updated_flex_target_kw = baseline_flex_target_kw.copy()
   updated_flex_target_kw[selected_position] = p_device_setpoint_kw

Finally, PandaProsumer is rerun to check whether the internal controller
can actually realize the OPF setpoint.

Example Result Interpretation
-----------------------------

In the current run, the selected timestep is:

.. code-block:: text

   2020-01-01 18:00:00+00:00

The PandaProsumer flexibility envelope is:

.. code-block:: text

   P_min  = 0.000000 MW
   P_base = 0.100000 MW
   P_max  = 0.280750 MW

This means the shopping center can operate between 0 kW and 280.75 kW of
grid-side consumption at the selected timestep, with a baseline of 100 kW.

The baseline grid state contains an undervoltage violation. The minimum
voltage before OPF is approximately:

.. code-block:: text

   V_min before OPF = 0.833334 pu

The OPF uses the baseline value as the reference:

.. code-block:: text

   p_reference = 0.100000 MW

and computes:

.. code-block:: text

   P_OPF = 0.010984 MW

So the mall grid consumption is reduced from 100 kW to 10.984 kW. The
activated grid-support flexibility is:

.. math::

   \Delta P_\mathrm{support}
   = P_\mathrm{base} - P_\mathrm{OPF}
   = 100.000 - 10.984
   = 89.016\ \mathrm{kW}

The corresponding PandaProsumer device-side target is:

.. math::

   P_\mathrm{CHP} - P_\mathrm{BHP}
   = 100.000 - 10.984
   = 89.016\ \mathrm{kW}

Therefore, the internal controller must provide approximately 89.016 kW of
net electrical support by increasing CHP generation, reducing BHP
consumption, or combining both actions.

After OPF, the minimum voltage improves to:

.. code-block:: text

   V_min after OPF = 0.900048 pu

This is just above the configured demonstration limit of 0.90 pu. The
result is therefore consistent with the minimum-deviation objective: OPF
uses only the amount of flexibility required to satisfy the active network
constraint.

The PandaProsumer rerun gives:

.. code-block:: text

   OPF setpoint           = 10.984 kW
   Updated PandaProsumer  = 10.985 kW
   Tracking error         = 0.000 kW

This validates the coupling. The pandapower OPF setpoint lies inside the
PandaProsumer envelope and is internally feasible for the shopping-center
model.

Plotting
--------

The function ``plot_results`` creates three plots.

Voltage profile
~~~~~~~~~~~~~~~

The first plot compares bus voltage before and after OPF. Buses are sorted
by their pre-OPF voltage, so the weakest buses appear first. This plot
shows whether flexibility activation improved the voltage profile and
whether the voltage limit was reached.

Mall dispatch bar plot
~~~~~~~~~~~~~~~~~~~~~~

The second plot compares:

* ``P_min``: minimum feasible mall consumption,
* ``P_baseline``: baseline mall consumption,
* ``P_max``: maximum feasible mall consumption,
* ``OPF ref``: baseline reference used in the OPF objective,
* ``OPF result``: OPF-selected grid-side mall power,
* ``OPF dispatch to mall``: PandaProsumer validation result.

The OPF reference is not a forced dispatch target. It is the baseline value
that the OPF tries to stay close to unless grid constraints require
flexibility activation.

Flexibility envelope plot
~~~~~~~~~~~~~~~~~~~~~~~~~

The third plot shows a 24-hour window around the selected timestep. It
plots:

* the baseline mall consumption,
* the ``P_min`` envelope,
* the ``P_max`` envelope,
* the OPF reference point,
* the OPF result,
* the updated PandaProsumer setpoint.

If the OPF result and PandaProsumer point overlap, the interface is
working correctly.

Function Overview
-----------------

``build_mall_prosumer``
    Builds the shopping-center prosumer model with CHP, BHP, heat storage,
    heat demand and optimization controller.

``run_mall_case_with_bounds``
    Runs the PandaProsumer time series, computes grid-side mall power and,
    when enabled, collects and converts device-side flexibility bounds into
    grid-side OPF bounds.

``run_pf``
    Runs an AC power flow and returns ``True`` if it converges.

``check_grid_violations``
    Checks undervoltage, overvoltage, line-overload and transformer-overload
    violations after a power flow.

``prepare_grid_for_opf``
    Fixes existing grid loads and generators, assigns voltage and loading
    limits and prepares the external grid for balancing.

``run_mall_opf_min_deviation``
    Runs the OPF with the mall as the only controllable load and minimizes
    deviation from the baseline mall consumption.

``plot_results``
    Visualizes voltage improvement, mall dispatch values and the flexibility
    envelope.

``main``
    Coordinates the full workflow: PandaProsumer baseline, bound collection,
    Schutterwald grid setup, violation check, OPF, setpoint conversion,
    PandaProsumer validation and plotting.
